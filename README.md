# Agent Runtime

> 初稿：探索一个具有持续内部状态的 Agent Runtime。本文记录当前讨论形成的设计方向，不代表所有机制已经定型。

> **实验性说明：** 本文中的公式均为实验性表达，用于明确当前假设和讨论边界，不是已经验证的规律，也不是必须采用的最终实现。函数形式、参数、向量维度及具体更新规则均未定。

## 核心想法

Agent 不只是一次次接收输入、调用 LLM、返回答案的流程。Runtime 持续维护内部状态，并在每次运行中允许这些状态发生变化。

当前讨论围绕三个机制展开：

- **Emotion**：高维连续状态，参与记忆读写，并影响 Runtime 的运行频率。
- **Memory**：由许多具有独立身份的记忆组成；每条记忆附带情绪向量，并根据使用频次动态分层。
- **Clock**：暂时抽象为系统的运行频率。它影响 Runtime 多久运行一次，不进一步规定记忆内部的细节机制。

LLM 则作为认知过程参与状态演化，而不是与 Emotion、Memory 并列的状态模块。

## Emotion

情绪暂时表示为一个高维向量：

\[
E_k \in \mathbb{R}^n
\]

当前不预设向量维度对应哪些人类情绪，也不预设固定的情绪基准状态或自然回归中心。

情绪更新遵循以下开放原则：

- 每次 Runtime 运行，都允许更新系统的任意状态，包括情绪本身。
- 情绪可以受到外部输入、记忆读取、认知过程和行动结果等因素影响。
- 情绪允许自我影响；向量各维度之间也自然允许相互作用。
- 情绪具有惯性：当前状态会对下一轮状态产生延续影响。
- 情绪是否存在稳定倾向，可能涉及系统的“动机”问题，暂不预设。

一个用于表达情绪自影响的实验性抽象是：

\[
E_{k+1}=f_E(E_k,\Omega_k)
\]

其中 \(\Omega_k\) 表示本轮可能影响情绪的其他状态、输入或认知结果。该表达只强调下一状态可以依赖当前情绪本身，不限定具体影响因素或函数形式。

情绪惯性可以进一步用一个实验性形式表达：

\[
E_{k+1}=\rho E_k+\Delta E_k
\]

其中：
- \(\rho E_k\) 表示当前情绪状态对下一轮的延续，即情绪惯性；
- \(\Delta E_k\) 表示本轮运行带来的情绪变化，可以综合来自外部输入、记忆、认知、行动结果以及情绪自身的影响。

该形式强调情绪不会在每轮更新时被完全替换，而是保留此前状态的一部分。这里的 \(\rho\) 暂时作为实验性惯性参数，不规定其取值、是否固定或是否需要扩展为更一般的变换。情绪惯性也不等同于向某个预设的中性状态回归，更不代表基于现实时间的衰减。

## Memory

Memory 是由多条具有独立身份的记忆构成的集合，而不是单一的当前状态。

每条记忆附带一个情绪向量，作为它的情绪印迹：

\[
A_i \in \mathbb{R}^n
\]

当前情绪与记忆情绪的点积：

\[
s_i(k)=E_k^T A_i
\]

用于表示当前情绪与该记忆情绪印迹之间的匹配程度，并影响该记忆的读写强度。

读写强度可以先抽象为：

\[
r_i(k)=g_r(s_i(k))
\]

\[
w_i(k)=g_w(s_i(k))
\]

其中 \(g_r\) 和 \(g_w\) 分别表示读取、写入强度的映射函数。一个可供实验的函数形式是：

\[
g_r(s)=\sigma(\alpha s),\qquad
g_w(s)=\sigma(\beta s)
\]

这里的 sigmoid 形式及参数 \(\alpha\)、\(\beta\) 仅是实验性示例，并非已确定的设计。读取与写入也不要求使用相同的映射函数。

初步原则：

- 新记忆可以记录产生时的当前情绪向量，作为其情绪印迹。
- 读取记忆不只是取出内容，也可以改变记忆自身状态，并影响当前情绪。
- 记忆根据实际使用频次动态分层，例如 Hot / Warm / Cold。
- 分层描述的是同一种记忆的不同访问层级，不是不同种类的记忆。
- 情绪匹配影响记忆此刻的读写强度；使用频次影响记忆的层级。两者是不同维度。

记忆分层的具体阈值、迁移规则、压缩方式和检索实现尚未确定。当前不为记忆使用频次引入基于现实时间的衰减公式。

## Clock

Clock 暂时定义为 Agent Runtime 的整体运行频率。

情绪对运行频率的影响可以先抽象为：

\[
f_k=g_c(E_k)
\]

其中 \(f_k\) 表示 Runtime 的运行频率，\(g_c\) 表示情绪状态到运行频率的映射。该式仅表达情绪可以影响运行频率，不规定具体函数、方向或幅度。

- Clock 决定 Runtime 的运行节奏。
- Clock 不直接规定记忆检索、写入或分层的内部算法。
- 记忆使用频次来自系统运行中实际发生的使用行为。

这里讨论的不是让每条记忆依赖现实时间戳、TTL 或物理时间衰减。现实时间可以用于外部调度；内部 Clock 暂时只作为 Runtime 运行频率的抽象。

## LLM：认知过程

LLM 是认知能力或认知算子，不是与 Emotion、Memory 并列的状态模块。

它参与当前状态下的理解、联想、推理、生成和决策，并产生可能影响系统状态的认知结果，例如：

- 对外部输入的理解；
- 对已有记忆的联想和推理；
- 新记忆内容；
- 行动或工具调用；
- 对内部状态的更新建议。

需要区分：

- LLM 的模型权重不等于 Agent 的记忆；
- LLM 的上下文窗口不等于 Agent 的长期记忆；
- LLM 生成的情绪描述不等于 Agent 的情绪向量；
- 单次 LLM 推理不等于 Agent 的完整状态演化。

暂时可以把关系抽象为：

\[
Y_k = LLM(X_k, S_k)
\]

\[
S_{k+1} = Update(S_k, Y_k, X_k)
\]

其中 \(X_k\) 是本轮外部输入，\(S_k\) 是当前系统状态，\(Y_k\) 是认知结果。每次 Runtime 运行都允许更新任意系统状态；具体状态更新不预设为固定步骤。

## 运行关系

    Emotion
      ├── Memory Read / Write
      └── Runtime Frequency

    Memory ◄────► LLM Cognition
      ▲                │
      └──── State Updates ────┘

    Clock ── controls Runtime execution frequency

这只是当前概念关系的示意，不规定具体执行顺序或实现架构。

## 当前设计原则

1. **减少预设**：不提前规定复杂的情绪类别、记忆类型或心理学模块，让结构尽可能从简单机制中产生。
2. **状态可演化**：每次 Runtime 运行都允许系统状态发生变化。
3. **机制相似，角色不同**：Emotion 与 Memory 可以共享向量、激活、交互和更新等基础机制，但它们的存在方式和系统职责不同。
4. **区分状态与过程**：Emotion、Memory 是内部状态；Clock 是运行机制；LLM 是认知过程。
5. **暂不把现实时间引入记忆机制**：Clock 先保持为 Runtime 运行频率的抽象。
6. **公式保持实验性**：数学表达用于探索机制，不提前固化未经讨论或验证的具体实现。

## 尚未决定

- 系统的动机是什么，以及它是否形成情绪的稳定倾向；
- 情绪向量如何具体更新，以及向量空间如何形成；
- 情绪惯性参数 \(\rho\) 的取值、是否固定，以及与情绪变化量的具体关系；
- 情绪点积如何具体映射为读写强度，是否采用示例中的 sigmoid；
- 记忆使用频次如何统计、如何分层和迁移；
- 记忆内容如何压缩、巩固或遗忘；
- Clock 的具体实现，以及情绪如何调节其频率；
- LLM 与 Runtime 之间的具体接口和执行协议。

## 记号约定

本文中的下标 \(k\) 表示 Runtime 的运行轮次，不表示现实时间。\(i\) 表示一条具体记忆；\(E_k\) 表示第 \(k\) 轮的当前情绪向量；\(A_i\) 表示记忆 \(i\) 附带的情绪向量；\(\rho\) 表示实验性情绪惯性参数；\(\Delta E_k\) 表示第 \(k\) 轮运行带来的情绪变化量。
