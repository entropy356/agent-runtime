# Agent Runtime Design

Agent Runtime 持续维护内部状态，并按自身频率运行。

## Emotion

Emotion 是持续变化的高维状态，不预设固定的人类情绪标签，也不设固定的中性基准。

它具有惯性，并在每轮运行中受当前状态、外部输入、认知与行动结果影响：

\[
E_{k+1}=\rho E_k+\Delta E_k
\]

Emotion 会影响 Memory 的读写强度，也可以影响 Runtime 的运行频率。

## Memory

Memory 由多条独立记忆组成，每条记忆带有与 Emotion 相似的高维状态表示。

当前 Emotion 与记忆状态之间的匹配程度影响记忆的读取与写入强度。

比较之前先减掉库内均值。自然语言向量的公共分量远大于彼此差异：实测 19 条 768 维记忆两两余弦均值 0.739、均值向量范数 0.868（互相独立时应约 0.23）。不减去它，匹配函数几乎恒定，读写强度对内容不敏感。中心化把「与库内平均相同」定义为 0，分数因此可正可负；均值随记忆库变化，不同库之间的分数不可直接比较。

记忆按实际使用频次动态分层，例如 Hot / Warm / Cold。分层表示访问层次，而不是不同的记忆类型；使用频次来自实际使用，不依赖现实时间衰减。Demo 1 用最近 16 个成功运行轮次中的自报引用频率划分层级，并为各非空层预留上下文名额；空缺名额按原检索分数补齐。频率随运行轮次变化，可升温也可降温；不直接作为检索分数加成。窗口、阈值和配额是当前实验策略，具体规则与局限见 Demo 说明。

读取与状态更新分开：读取本身不直接改变 Emotion 或 Memory；LLM 完成本轮认知后，再统一更新系统状态。

## Clock

Clock 表示 Runtime 的整体运行频率。

Emotion 可以影响该频率，但 Clock 只控制系统运行节奏，不直接规定记忆检索、写入或分层算法。现实时间只用于外部调度。

## LLM

LLM 是认知过程，而不是持续状态本身。它基于外部输入和当前状态进行理解、联想、推理、生成与决策，并产生状态更新所需的结果。

```text
Current State + External Input
              ↓
        Memory Retrieval
              ↓
         LLM Cognition
              ↓
          State Update
        ┌─────┼─────┐
        ↓     ↓     ↓
     Emotion Memory Other State
        │
        └──────→ Clock Frequency
```

其中运行轮次不等同于现实时间。LLM 的上下文和模型权重也不等同于 Agent 的持续状态。
