# 项目愿景：信息化历史

目标不是保存更多历史，而是让有价值的信息能够从项目本身恢复，并形成可比较的数据。

- 代码和文档只描述当前状态，不额外维护旧版本、时间线或方案演化记录。
- 实现如何变化交给 Git 保存，不在当前文件中重复历史。
- 只有具有长期比较价值的实验条件、原始结果和指标才单独保留，并关联对应版本。
- 实验记录跟随产生它的 Demo；跨 Demo 的比较和项目级总结进入 `docs/`。
- 仍然有效的结论直接合并进当前设计；失效的叙述不继续占据主文档。
- 需要回顾时，可以从 Git、实验数据和当前状态中按需重建比较与演化过程。

因此，历史不是一套需要持续维护的平行文档，而是项目状态、Git 记录和必要实验数据共同留下的信息。实验数据负责提供比较依据，Git 负责提供可追溯的实现版本，当前文档负责表达仍然有效的知识。
